## Launch-path enumeration (the plan's explicit request)
Every place in today's code that can start Capture One, checked at HEAD `33b9eca`:
- **Scripts that launch when addressed** (no `running()` guard): `launch` (`open -g -a "Capture One"`, `jxa.rs:129–130`), `make_document`, `open_document`, `front_document`, `ensure_recipe`, `ensure_capture_style`. This matches the plan's six exactly. The other 15 scripts (`capture`, `document_info`, `editor_info`, `find_image*`, `get_*`, `import`, `process`, `recipe_exists`, `save`, `set_*`) all check `running()` first. `quit.js` (new) must join that group (L13).
- **Callers of the six:** only `provision.rs` (`:83` launch, `:142` make, `:188` open, `:228` recipe, `:263` style, `:308` front), always through `CaptureOneAdapter.user`, which is the `GatedScripting` user lane (`lib.rs:377–378`, `adapter.rs:51–52`). The background lane calls only guarded scripts. `CameraViaCaptureOne` calls only `capture` (guarded). The ungated `App.scripting` has no caller at HEAD (P48 adds `save`/`quit`).
- **Paths into `ensure`/`bring_document_to_front`:** `EditingStartup::run` from `AppHandles::health_check` (`lib.rs:205`; `health_get`, Retry checks), from the startup thread of every `App::build` with `run_startup` (`lib.rs:639`; app start, settings rebuild, `reopen`) and from `App::startup` (`lib.rs:797`; tests only); and `SessionsService::activate` (`sessions.rs:58–59`; `commands/sessions.rs:412`). `deactivate` calls only guarded scripts.
- **Non-Capture-One process spawns:** `osacompile` for the hooks (`hooks.rs:48`), `/usr/bin/open <folder>` (`commands/export.rs:48`), the sidecar. None addresses Capture One.
- **Conclusion:** gating the six methods of `GatedScripting` (both lanes) covers every launch path at HEAD, provided L1 (callers stop after a deferral), L13 (`quit.js` guard) and L14 (the gate is process-wide, so a settings rebuild cannot produce an ungated lane) are folded.
