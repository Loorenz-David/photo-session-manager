## Finding → what changed → files
**F1 (B1) — after a relaunch captures go to the last opened session while the UI shows none open.**
Chose the first offered correction: make the UI show the session the backend has active.
- `SessionsService::active()` returns the stored `active_session_id` (`crates/core/src/services/sessions.rs`).
- New thin command `session_active` returns that session (or null) (`src-tauri/src/commands/sessions.rs`, registered in
  `lib.rs`; `bindings.ts` regenerated by `export_bindings`).
- `activeSession()` service wrapper (`services/sessions.ts`).
- `App.tsx` `useResumeActiveSession`: once at launch, if a session is active and the route is still `#/` or empty,
  navigate to it. A session/health route the user already chose is left alone; a failed read shows an error toast.
- No race with P04's background startup: the UI only reads the stored id; nothing is written, and `EditingStartup`
  is unchanged. Returning to Sessions still calls `session_deactivate` (S-E).
- Tests (services boundary): frontend `F1 a session left active by the last run is opened at launch…` (hash becomes
  `#/session/9`, view shown, no `deactivateSession` call) and `F1 with no active session the app opens on the
  Sessions list`; Rust `f1_active_reports_the_stored_active_session` (None, then the stored id).
