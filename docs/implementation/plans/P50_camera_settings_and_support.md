# P50 — Camera settings and support packages (10E §Camera support packages R-I36, MC-31 R-I21, R-I18, chapter 12)

## Goal
The backend of camera setup. **Support packages** (R-I36, owner D7/R45): `camera_support_install(archive)` extracts the Sony Camera Remote SDK archive the
user downloaded (the app extracts it itself, so no quarantine attribute reaches the copies), verifies every runtime file against the compiled-in
manifest (`native/camera-sidecar/manifest/sony-<version>.json`: names and SHA-256 only, generated on the build machine by `tools/sidecar/manifest.sh`),
copies the runtime and **a copy of the bundled sidecar** into `<data dir>/camera/sony/<version>/`, signs the Mach-O files ad hoc (with the entitlement
P47's spike S2 recorded, if any), runs the copy's `version` and requires a supported SDK version; at each start the copy is compared with the bundled
sidecar and refreshed; a missing or wrong file refuses the install and names the file. **Secrets** (R-I21): `camera_secrets_set` writes the Access
Authentication user and password to the Keychain and applies R-I18's restart rule (restart the sidecar only while it holds no USB session, else at the
next spawn); `camera_ftp_password_generate` makes the 32-character password, stores it, shows it **once**, and reopens the receiver in place. **Fingerprint**
(MC-31 §Fingerprint): the sidecar reports the unpinned fingerprint, the app raises `camera_fingerprint_pending`, and `camera_fingerprint_confirm` lets the
sidecar pin it on the next connect (`reject` pins nothing). Health: `camera_support_not_installed` for an installed-but-invalid support folder.
**Not in this phase:** the screens (P51), the camera (P52), FTPS, any vendor file in the repo.

## The contract
- **Manifest:** `Manifest { version: "2.02.00", files: [{ path: "libCr_Core.dylib", sha256 }, { path: "libmonitor_protocol.dylib", … }, { path:
  "libmonitor_protocol_pf.dylib", … }, { path: "CrAdapter/libCr_PTP_USB.dylib", … }, { path: "CrAdapter/libCr_PTP_IP.dylib", … }, { path: "CrAdapter/
  libssh2.dylib", … }, { path: "CrAdapter/libusb-1.0.0.dylib", … }] }` — exact names from the manifest file, compiled in with `include_str!`.
  `SUPPORTED_SDK_VERSIONS` = the versions of the compiled-in manifests. **The manifest is generated on the build machine from the lab's `vendor/sony-sdk`
  by `tools/sidecar/manifest.sh`; the repo holds hashes, never a Sony byte.**
- **Install:** `install(paths, archive, bundled_sidecar)`: open with `zip`; refuse a non-zip (`SupportArchiveInvalid { file: <archive name> }`); for each
  manifest entry find the archive entry whose path ends with the manifest path (the lab's glob rule; several → the first in archive order); missing →
  `SupportArchiveInvalid { file: <manifest path> }`; extract each to `<data dir>/camera/.install-<uuid>/<path>` (streamed; the Rust process writes plain
  files — no quarantine xattr); SHA-256 ≠ manifest → `SupportArchiveInvalid { file }` and the temp folder removed; copy `CrAdapter/` also to `Contents/
  Frameworks/CrAdapter/`; copy `bundled_sidecar` to `camera-sidecar` (mode 0o755); `codesign -s - --force [--entitlements <plist>]` on every file whose
  first 4 bytes are a Mach-O magic (`FEEDFACF`, `FEEDFACE`, `CAFEBABE`, `CFFAEDFE`) — the entitlements plist (`com.apple.security.cs.disable-library-validation`)
  is used **iff P47 recorded S2 = needed** (a const `SIDECAR_NEEDS_LIBRARY_VALIDATION_OFF: bool` the orchestrator sets from the spike before dispatch); run
  `<temp>/camera-sidecar version` (3 s timeout) → parse `crlab.version`: `sdk_compiled_in == false` → `SupportVersionUnsupported { version: "unavailable" }`;
  `sdk_version ∉ SUPPORTED` → `SupportVersionUnsupported { version }`; refusals remove the temp folder; success → rename the temp folder to `camera/sony/
  <sdk_version>/` (an existing folder of that version is replaced by renaming it aside first and removing it after), then `runtime.support_changed()`
  (bind rule (c): spawn + receiver now). `installed(paths)` = the newest version folder holding **every** manifest file and `camera-sidecar`; a folder
  missing any → health `camera_support_not_installed` (detail `Camera support for Sony is damaged: add it again in Settings → Camera`) and the Capture One
  camera adapter is used. `refresh_sidecar_copy(paths, bundled)` at every bind: SHA-256 of the copy ≠ bundled → copy + sign again (R-I36).
- **Secrets:** `CameraService::set_secrets(user, password)` → `secrets.set(ACCESS_AUTH_USER, user)`, `set(ACCESS_AUTH_PASSWORD, password)`, `logging::add_secret`
  for both, `runtime.secrets_changed()` → if the sidecar runs **and** the current session is not USB → `quit_and_wait` + spawn (new pid, new credentials line);
  if on USB → nothing now (the new values are read at the next spawn); not running → nothing. Never echoed by any command. `generate_ftp_password()` →
  `ftp_password(getrandom)` (32 chars from `[A-Za-z0-9]`, rejection sampling) → `secrets.set(FTP_PASSWORD, pw)`, `add_secret(pw)`, `runtime.ftp_password_changed()`
  → the receiver stopped and started with the new password (one listener; same port), and the password returned **this once** (`camera_ftp_password_generate`
  → `{ password }`); there is no command that reads it back.
- **Fingerprint:** P45's `SshFingerprint { status, fingerprint: Option<String> }` (the C++ adds `fingerprint` = the SDK's fingerprint bytes as lowercase hex
  with `:` separators, as the camera menu shows them) → `status == "unknown"` → `NeedsAction { FingerprintUnconfirmed }` **and** `AppEvent::FingerprintPending {
  fingerprint }` (→ Tauri `camera_fingerprint_pending`); `confirm_fingerprint()` → `client.send(AcceptFingerprint { replace: false })` (the sidecar pins it
  on the next connect, as the lab's `--accept-fingerprint` did); `reject_fingerprint()` → nothing is sent, the item stays until the next confirm; `status ==
  "MISMATCH"` → `NeedsAction { FingerprintMismatch }`, `FingerprintPending` with the new value, and `confirm_fingerprint()` then sends `AcceptFingerprint {
  replace: true }` (the sidecar deletes the pinned file first). No `connect` retry is forced by the app; the sidecar's own backoff retries.
- **Health:** the camera items already derive from the adapter's status (P42/P46); P50 adds `camera_support_not_installed` as above and makes
  `health_items` include `camera_fingerprint_*` with the §6.6 details (already) — nothing else.
