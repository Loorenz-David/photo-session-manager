# Backlog — R2_research_foundation (reviewer notes; none blocks)

- **R2 reviewer r1 (note → R6): the session row shows nothing for a held publish.** `StatusPill.tsx` switches on `label.kind` with no `waiting_for_you` branch, so `RowLabel::WaitingForYou(n)` renders an empty status cell. Nothing produces `held` until R5·U2, so no user sees it today. R6 must add the pill "Waiting for you · n conflicts" (08B MC-A10, status and label). Why: once R5 ships, a held session would lose its status pill and its activity popover.
- **R2 reviewer r1 (note → R5·U2): two derivations of the held conflict count.** The session list counts pending keys without an entry in `resolved_attributes` (`store.rs`, session list); the publish activity text (`services/publish.rs`, `PublishStep::Held` arm) uses `pending_conflicts.len() - resolved_attributes.len()`. They agree only while every resolved key is also pending. R5·U2 should use one helper (MC-A10: "n = pending keys without a resolution"). Why: the row and the popover could show different numbers for the same item.
- **R2 reviewer r1 (note): the research copy carries no colour profile.** `render_research` reuses the MC-28 renderer, which embeds the sRGB ICC profile (APP2), then strips every APPn and COM segment, the profile included. Pixels are sRGB and untagged JPEGs are read as sRGB by convention, so this meets MC-A5 ("sRGB, all metadata removed"). Why: if a provider is ever seen to misread colours, keep APP2 and strip only the rest.
