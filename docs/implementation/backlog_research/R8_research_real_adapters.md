- **R8 reviewer r1 (note): the page reader's address guard could cover more non-public ranges.** `adapters::http::is_public` refuses what the plan's contract names: loopback, private, link-local and unspecified, plus broadcast and 0/8, with IPv4-mapped IPv6 unwrapped. It lets through shared address space `100.64.0.0/10` (CGNAT; some home routers and VPNs answer there), `192.0.0.0/24`, `198.18.0.0/15`, multicast (`224.0.0.0/4`, `ff00::/8`), deprecated site-local `fec0::/10`, and the IPv6 forms that embed an IPv4 address (`64:ff9b::/96` NAT64, `2002::/16` 6to4). Why: page URLs come from search results; refusing these too costs a few lines in one function.
- **R8 reviewer r1 (note): environment proxies bypass half 2 of the address guard.** reqwest 0.13 reads `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` by default, even with `default-features = false` (`proxy.rs` `system()`). Through a proxy, the page host is resolved by the proxy, not by the `PublicOnly` resolver. Half 1 (no IP literal, no `localhost`) still applies. Why: an app started from a shell that has a proxy variable set would let a search result reach a local name; `.no_proxy()` on the `PublicOnly` client closes it.
