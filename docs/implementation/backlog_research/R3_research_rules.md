# Backlog — R3_research_rules (reviewer notes; none blocks)

- **R3 reviewer r1 (note → R4·U4): a call costs nothing when its (provider, model) has no fallback price.** `rules::cost::call_cost` returns 0 when the usage is missing (or names an unknown unit) and the price table has no `fallback_call_usd` for the pair (implementer assumption 19, relying on MC-A6 `PriceMissing`). R4·U4's `PriceMissing` check must therefore cover **every** (provider, model) a run can call, including the non-model providers with model `""` (visual search, page reader), not only the stage 7 model. Why: otherwise a timed-out call is recorded at 0 micro-USD, the run cap and the day cap undercount, and MA15 ("the fallback when no usage was reported") silently fails.
- **R3 reviewer r1 (note → R6 / R4·U3): a field listed in both the Details and the Product step is researched.** `writes::layout_step` returns the first step (order Details, Condition, Product) whose resolved layout lists the key, and `presets_set` does not stop a Details definition from also being placed in the Product layout. Such a key is then treated as a Details field and written, although MC-A1 says "any `product`-step field" is never written. Fail closed would be: never written when **any** step that lists the key is Product. Why: narrow (needs a hand-built layout), but it is the one path where research could fill a field the publication assistant owns.
- **R3 reviewer r1 (note → R8·U1–U3): 401/403 with the quota flag is classified `key`.** `rules::calls::classify` checks 401/403 before the quota flag (assumption 18). Both classes fail the run, but the run's text becomes "key rejected by <provider>" where the provider meant "no credit". R8's adapters should check the providers' real quota replies (RESEARCH-VERIFY-2, -3, -11) and set the flag only where status ≠ 401/403, or the order should flip. Why: the owner would hunt for a bad key when the account is simply out of credit.
- **R3 reviewer r1 (note → book 08B, orchestrator): MC-A4's invariant contradicts its own visible and condition tables.** The invariant says "No research value is above `low` without a label item, a shop `match`, or `match` items on two distinct trusted identities stating it", yet the visible table writes a sure photo read with no listing at `medium` (row A05·C3(d)) and the condition paragraph writes a sure read at `medium` (A05·C4(b)). The code follows the enumerated rows, which is right. The invariant should say it holds for attribution and measured fields. Why: a later reviewer or property test written from the invariant would call correct code wrong.
